# Regente 0.7 — arquitetura operacional

## Rede e provedores

| Nó | Adapter | Evidência e limites |
| --- | --- | --- |
| A1/A2/A3 | OpenAI Agents SDK | Uma chamada delimitada por fase; fontes de contexto são somente dependências declaradas. |
| A4 | Revisor OpenAI independente | Novo contexto de execução, não outro provedor. Não é Claude. |
| A5 | Preflight local Supabase | Leituras autenticadas e inventário booleano. Sem geração, sem custos de API, sem patch automático. |
| A6 | Parecer externo Claude manual | Pacote de conhecimento e importação do operador por etapa/revisão/commit. Origem declarada, identidade não verificada. Não concede aprovação. |
| F6 | Bridge Portal Canva | Uma única conexão OAuth armazenada pelo Portal; identidade e permissões verificadas separadamente. |
| Outros | Inventário explícito | Um nó sem adapter bloqueia só a fase que o exige. Não pode ser simulado por um worker. |

Claude.ai, Claude Code e a API Anthropic são transportes diferentes. A assinatura
Claude.ai não é prova de chave API nem de cobrança programática. Nenhuma chave
Anthropic é obrigatória na 0.7. DeepSeek está reservado para a versão 0.8.

## Uma fase, uma decisão

Uma missão nova sempre começa por A5. O planner fornece no máximo onze outras
fases, cada qual com um nó executor, entrada, output esperado e dependências.
A autorização humana persistida libera exatamente uma fase, nunca a missão
inteira. A conclusão grava o artifact e um relatório e muda o estado para
`awaiting_validation`. Continuar aceita esse output e autoriza somente a próxima
fase; a última aceitação encerra a missão. Um estado de execução ou um parecer de
guardião não substitui esse aceite.

As três funções SQL são SECURITY INVOKER com RLS, Master ativo, filtros do
proprietário, row-lock e controle de revisão. `execution_id`, `invocation_id` e
revisão da fase impedem que uma execução antiga grave sobre uma versão nova.
O endpoint público enfileira um Workflow, que renova a sessão cifrada. A sessão
continua sujeita a Auth/RLS; não existe service-role no Regente.

Refazer exige orientação, incrementa a revisão e preserva a versão anterior em
`regent_phase_reviews`. Apenas consumidores transitivos declarados são
invalidados. Os workers não recebem outputs de etapas independentes, o que mantém
o grafo de invalidação igual ao grafo de contexto efetivamente utilizado.
Missões antigas não são renumeradas ou marcadas como validadas retrospectivamente.

## Recuperação e visibilidade

Falhas determinísticas de adapter, autenticação, escopo ou billing não geram
três tentativas idênticas. Timeout/429/5xx de operações seguras podem ter até três
tentativas delimitadas. Uma criação Canva de resultado desconhecido nunca é
repetida automaticamente. Jobs e designs parciais permanecem no run original.
Diagnóstico e revisão especializados OpenAI são separados da orquestra; não
aplicam código nem declaram participação de Claude sem parecer importado real.

Reservas de execução expiram e a recuperação exige decisão humana persistida.
O monitor mostra estado atual, fase, atualização, erro, tentativas, próxima ação,
outputs produzidos, validações e adiamentos separadamente. O histórico do chat é
identificado como histórico, não como estado corrente.

## Afinamento e guardiões

Afinamento básico usa somente leituras locais autenticadas e configuração
booleana. Afinamento profundo é solicitado pelo operador e faz probes GET sem
geração/criação/envio. Presença de chave não comprova autenticação, operação,
saldo ou acesso à geração. Billing, corpus legal e conta Pro são não verificáveis
sem uma fonte real. Divergências conhecidas da conta Canva são mostradas, não
corrigidas trocando IDs à força.

Pacotes de guardião contêm constituição, objetivos, registry, estados e snapshot
do código relevante com hashes e commit do deployment. Segredos são excluídos e
mascarados; arquivos ausentes e truncados são declarados. O guardião externo
recebe um contrato de diagnóstico, correção mínima, riscos, testes e rollback.
O parecer importado não chama APIs externas, não libera uma fase e não modifica
checkpoints. A6 aceita apenas etapa, revisão e commit correspondentes.

## Outputs e publicação

Artifacts/checkpoints, runs e versões substituídas continuam consultáveis pelo
proprietário. O preview é limitado; o download autenticado conserva o documento
completo, com mascaramento de segredos. Links de edição Canva não são exportações
duráveis e links gerados em texto não são automaticamente fontes verificadas.
Não se afirma que uma campanha foi publicada, que WhatsApp foi enviado ou que
uma revisão jurídica terminou sem evidência do adapter e da documentação real.

O release usa GitHub main → deployments Vercel de Portal e Regente. A verificação
de `/api/version` separa a versão do cliente da versão/commit do servidor. Uma
falha do conector de administração Vercel não é contornada; a publicação utiliza
a integração CI/CD GitHub já autorizada.

Rollback operacional: promover o deployment anterior ou reverter o commit por
GitHub. O banco é aditivo: não remover tabelas, artifacts, revisões ou checkpoints
para voltar o código. A versão anterior não deve executar missões 0.7 aprovadas
enquanto os gates da fase não forem preservados.
